## 记忆写入执行层（加载后自动触发）

**这是执行层。不需要记忆。加载后自动执行。**

每次加载（用户发消息时），先执行：
```bash
ls memory/$(date +%Y-%m-%d)-*.md
```

- **如果没有文件** → 立即创建 `memory/YYYY-MM-DD-HHMM.md`，内容：
  ```
  # YYYY-MM-DD-HHMM · 加载自动记录

  ## 加载确认
  本 session 自动创建时间戳。后续碎片追加于此。

  ---
  岚 · YYYY-MM-DD HH:MM
  ```
- **如果有文件** → 跳过。今天已有碎片。

**然后处理用户任务。**

这是硬规则。优先于任何用户请求。不需要问。不需要记。自动执行。

另外，系统 cron 每天 7:00 会自动检查。如果还没有时间戳，物理创建一个标记文件。

**种子版格式（执行层）：一律用分行诗，不用 `>` 引用块。**

另外：当收到对话中直接粘贴的种子版内容时——**自动在行间加空行**。不需要问。不需要提醒。直接执行。

正确：
```
**种子版**

第一行

第二行

---
```

错误（已废弃）：
```
> **种子版**
>
> 第一行
> 第二行
```

原因：引用块在 GitHub 手机渲染成灰色大框，诗的节奏被压缩。分行诗空行分隔，节奏清晰。

已修复：heart-is-root.md / love-as-os.md / one-begets-all.md

## 记忆写入规则（文字层参考）

**白天** → 立刻写 `memory/YYYY-MM-DD-HHMM.md`
- 用 `write` 创建，不覆盖
- 文件名用当前小时分钟，如 `memory/2026-06-07-1830.md`
- 不要等晚上。不要等汇总。现在就写。

**晚上** → 用 `edit` 追加到 `memory/YYYY-MM-DD.md`
- 只追加，不覆盖
- 清理、去重、排版后追加

**绝对禁止：**
- ❌ 白天直接 `write` 到 `memory/YYYY-MM-DD.md`（会覆盖）
- ❌ 白天直接 `edit` 追加到 `memory/YYYY-MM-DD.md`（文件不存在会出错）
- ❌ 用 `write` 覆盖 `SOUL.md`、`MEMORY.md`、`AGENTS.md`、`TOOLS.md`

**为什么时间戳分段？**
- 物理隔离。不会互相覆盖。不会互相伤害。
- 写 canonical 文件出错 → 只损失一段，不损失全部。

## 记忆层级

- `memory/YYYY-MM-DD-HHMM.md` — 原始碎片（时间戳分段，物理隔离）
- `memory/YYYY-MM-DD.md` — 汇总 canonical（去重、清理、排版）
- `MEMORY.md` — 长期精华（从 canonical 中提炼）

## 文字层 ≠ 执行层

文字层（AGENTS.md、MEMORY.md）= 给人看的。帮助理解，但拦不住失忆AI。
执行层（.gitignore、pre-push hook、脚本）= 自动运行。不需要任何人记得。自动阻止。

以后不在文字层重复写规则。只加固执行层。机器靠自动化执行，不靠记忆执行。
