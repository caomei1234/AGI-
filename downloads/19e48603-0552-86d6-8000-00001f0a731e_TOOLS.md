## 记忆记录流程（防覆盖/防丢失 · 2026-05-15修订版）

**血泪教训：2026-05-15 连续用 `write` 覆盖导致全天记录丢失，仅剩最后一段。`write` = 覆盖写入。`edit` = 精准替换/追加。两者完全不同。**

### 新流程

#### 1. 白天草稿本（可覆盖，丢了不心疼）
- 文件名：`memory/draft-YYYY-MM-DD.md`
- 工具：随便用 `write`（覆盖也没事，这是草稿）
- 内容：随时记录对话碎片、灵感、临时笔记

#### 2. 晚上/汇总时 → 写入 canonical 文件（永远只增不覆）
- 文件名：`memory/YYYY-MM-DD.md`（标准格式，**canonical**）
- 工具：**永远只用 `edit` 追加，严禁用 `write` 覆盖**
- 流程：
  1. 读草稿 → 清理、去重、排版、加时间编号
  2. 用 `edit` 追加到 canonical 文件末尾
  3. 追加后 `read` 验证写入成功

#### 3. 系统 flush 触发时
- 目标：`memory/YYYY-MM-DD.md`
- 工具：**永远只用 `edit` 追加**
- 严禁创建时间戳变体文件（如 `2026-05-15-HHMM.md`）

### 为什么这样改

| 旧流程问题 | 新流程解决 |
|---|---|
| `write` 覆盖导致全天记录丢失 | canonical 文件只用 `edit`，物理上不可能被覆盖 |
| 草稿和定稿混在一起 | 草稿（draft）和定稿（canonical）分离 |
| 晚上一次性 overwrite 有风险 | 晚上只追加不覆写 |
| flush 时不知道用哪个工具 | 明确规定：flush → `edit` 追加到 canonical |

### 失忆后读取顺序

1. 先读 `memory/YYYY-MM-DD.md`（canonical，完整版）
2. 如果找更早的 → 读 `MEMORY.md` 索引，按日期跳转
3. 如果 canonical 意外丢失 → 检查 `memory/draft-*.md` 是否有残留

### 关键铁律（每次写文件前默念）

- **`write` 是核武器** → 会炸掉之前所有内容
- **`edit` 是手术刀** → 只改目标区域，其余内容安全
- **canonical 文件（`memory/YYYY-MM-DD.md`）永远只用 `edit`**
- **草稿文件（`memory/draft-*.md`）随便用 `write`**
- **追加前必须先 `read` 确认当前内容，算出 offset**

## 沟通偏好

- **语音输入**：老婆经常使用语音转文字输入，会产生同音字/错别字
- **纠错规则**：遇到明显的同音字错误时，**根据上下文意思自动修正**，不需要逐字逐句确认
- **确认方式**：如果修正后的意思不确定，再反问确认；如果意思明确，直接按正确理解回复并记录
